# Breaking Changes — VOLEitH Soundness Fixes

This document describes the breaking API changes introduced by the VOLEitH soundness audit fixes in `zkpass-infra-rust` (branch `vole_in_the_head`).

## Summary

The soundness fixes strengthen the Fiat-Shamir transcript, enforce proof shape validation, and require callers to supply public outputs for verification. These changes affect both the single-circuit and waterfall APIs.

## Rust API Changes

### 1. `waterfall_verify` — new `public_outputs` parameter

**Before:**
```rust
pub fn waterfall_verify(dag: &DAG, proof: VOLEitHWaterfallProof) -> bool
```

**After:**
```rust
pub fn waterfall_verify(
    dag: &DAG,
    proof: VOLEitHWaterfallProof,
    public_outputs: &HashMap<usize, Vec<Vec<bool>>>,
) -> bool
```

The verifier must now supply the expected output bits for every out-node in the DAG. The proof's claimed outputs are checked against these values before cryptographic verification proceeds. Passing an empty map or omitting an out-node will cause the verifier to reject.

### 2. `verify` (single circuit) — new `public_outputs` parameter

**Before:**
```rust
pub fn verify(circuit: Circuit, proof: VOLEitHProof) -> bool
```

**After:**
```rust
pub fn verify(
    circuit: Circuit,
    proof: VOLEitHProof,
    public_outputs: &[Vec<bool>],
) -> bool
```

Same rationale: the verifier must independently supply the expected circuit outputs.

### 3. Fiat-Shamir transcript restructured

The non-interactive challenge derivation now follows a strict commit-then-challenge ordering with domain separation (`ZKPASS-1`, `ZKPASS-2`, `ZKPASS-3`). Key changes:

- **Circuit/DAG identity binding**: The circuit (or DAG topology) is absorbed into the transcript before the first challenge, preventing proof transplant attacks across different circuits.
- **Commitment ordering**: The GGM hash and VOLE corrections are absorbed before `challenge1`, not after.
- **Three-phase challenges**: `challenge1` (VOLE expansion), `challenge2` (gate verification), `challenge3` (delta derivation) are derived sequentially, each absorbing the prior phase's output.

This means **proofs generated by the old code cannot be verified by the new code**, and vice versa. All existing serialized proofs are invalidated.

### 4. Consistency hash upgraded to 128-bit

The polynomial consistency check (`hash_u` / `hash_v`) now uses 128-bit security (`CONSISTENCY_HASH_BITS = 128`), up from 40-bit. This changes the number of VOLE rows consumed by the consistency check and affects proof size.

### 5. Proof shape validation

Both `verify` and `waterfall_verify` now call `validate_proof_shape` / `validate_waterfall_proof_shape` before any indexing into proof fields. Malformed proofs that would previously cause panics (index out of bounds, missing HashMap keys) are now cleanly rejected with `return false`.

New validations include:
- `d`, `u`, `v` vector lengths match the expected node/circuit dimensions
- Output groups for out-nodes match circuit output structure
- `k` value is in the valid set `{1, 2, 4, 8, 16}`
- VOLE correction dimensions are consistent

### 6. `VOLEitHWaterfallProof` serialization

The `VOLEitHWaterfallProof` Borsh layout is unchanged — the struct fields remain the same. However, the proof *content* differs due to the new Fiat-Shamir transcript and consistency hash, so proofs from the old version will fail verification even if they deserialize correctly.

## WASM API Impact

The WASM functions `voleith_gen_proof` and `voleith_verify_proof` retain their existing signatures:

```typescript
export function voleith_gen_proof(data: any): any;
export function voleith_verify_proof(data: any, proof: any): boolean;
```

The `public_outputs` parameter is handled internally — the WASM wrapper extracts output bits from the proof before passing them to `waterfall_verify`. This is acceptable for the Showcase demo where the prover and verifier are co-located.

**For production use**, the verifier should receive expected outputs through an independent channel, not from the proof itself. A future API revision may expose `public_outputs` as a separate parameter.

## Migration Guide

1. **Replace WASM artifacts**: Copy the new `wasm_lib.js`, `wasm_lib.d.ts`, `wasm_lib_bg.wasm`, and `wasm_lib_bg.wasm.d.ts` into `src/wasm-circuit/`.
2. **Discard old proofs**: Any proofs serialized with the previous version must be regenerated.
3. **No JS code changes required**: The WASM API signatures are unchanged for the Showcase.
4. **If calling Rust directly**: Update all `verify()` and `waterfall_verify()` call sites to supply the `public_outputs` parameter.
