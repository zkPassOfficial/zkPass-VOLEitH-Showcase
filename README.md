# zkPass-VOLEitH-Showcase

A Next.js page that builds four statements in TypeScript and calls a vendored WebAssembly prover and verifier. Package name `vole-in-the-head-showcase`, version `0.1.0`, `"private": true`. The Rust sources that produced `src/wasm-circuit/` are not in this repository, and `src/wasm-circuit/package.json` does not record a build commit. This documentation pass did not install dependencies, run the page, or inspect the wasm binary.

The cards call that module in the browser. The Web Proof card loads the same-origin file `public/fixtures/session.json` with `fetch("/fixtures/session.json")`. `src/statements/webproof.ts` says that fixture was generated by `real_circuit/session.rs`. That Rust file is not in this tree.

## Cards

| card | statement in source | public output the card reads |
| --- | --- | --- |
| Compare | `a <relation> b` over two 64-bit numbers (`src/statements/compare.ts`, `BITS = 64`) | one bit, `outputs[0].groups[0][0]` |
| AES | AES-CTR: each block is an AES-128 node, an XOR, and an equality, ANDed into one bit (`src/statements/aes.ts`) | one bit |
| Anonymous Fingerprint | two AES-256 nodes; the comment describes their outputs as the 32-byte fingerprint (`src/statements/fingerprint.ts`) | those output bytes |
| Web Proof | statement bytes taken from the synthetic session fixture (`src/statements/webproof.ts`) | the fixture's revealed field plus the statement bit the card displays |

The demo UI also renders the inputs it built locally. `verify` in `src/zk-build/index.ts` receives statement bytes and proof bytes, not the witness array.

Failure paths in the TypeScript, separate from the walkthrough animation:

- every card can flip a proof byte in the shared card component's break actions
- Compare exposes `otherStatement`, the opposite relation
- AES exposes `falseClaim`, which replaces the claimed plaintext
- Web Proof exposes `falseClaim`, which replaces the claimed address, and `otherStatement`

`src/walkthrough.ts` replays prover and verifier steps for display. It is not a test, and this repository has no test script and no tracked GitHub Actions workflow.

## What the TypeScript calls

`src/zk-build/index.ts` loads the wasm module with `ready`, which calls `init()`. Statements cross the boundary as Borsh bytes:

- `statementBytes(statement)` serializes `Waterfall`
- `proofInput(statement, witness, k)` serializes `WaterfallInput` with `k` typed `4 | 8`
- `prove(input)` calls `voleithGenProof` and returns `{ proof, ms }`
- `verify(statement, proof)` calls `voleithVerifyProofOutputs` and returns `{ outputs, ms }`. The comment says it throws with the library message when the proof is malformed or rejected
- `proofSections(proof)` returns section names and sizes

The paper cited by the previous write-up is [eprint 2023/996](https://eprint.iacr.org/2023/996). This repository does not include a proof-format integer in the TypeScript sources. Claims that the vendored module is proof format version 9, or that a particular optimization makes proofs 8 times smaller, 10 times faster, or 10 times smaller in memory, are not backed by a baseline build, a comparison script, or a measurement log in this tree. `src/benchmarks.json` records absolute medians only:

- `machine`: `Apple M-series, 10 cores`
- `browser`: `Chrome 154`
- `date`: `2026-10-03`
- `infraCommit`: `0a3d200`
- `method`: `median of 7 runs on the page, k = 8, the cards' default inputs`
- rows `compare`, `aes`, `fingerprint`, and `webproof`, each with `k`, `proveMs`, `verifyMs`, and `bytes`

Those fields are the file's contents. This documentation pass did not reproduce them. The page copy in `src/pages/index.tsx` says a larger `k` costs more proving time and points at the on-page measurements. It is UI text, not a result from this pass.

## Install, build, run

`package.json` does not set `engines`. The lockfile header is `yarn lockfile v1`. Scripts are `dev` (`next dev`, Next.js default port 3000), `build` (`next build`), `start` (`next start -p 9018`), `lint` (`next lint`), and `format`.

```bash
yarn install --frozen-lockfile
yarn lint
yarn build
yarn start
yarn dev
```

`yarn start` serves `http://localhost:9018` because of `-p 9018`. This documentation pass did not run Yarn or Next.js.

## Example

The call shape matches `src/zk-build/index.ts` and `src/statements/compare.ts`. `holds` in `compare.ts` is the TypeScript predicate `a > b` for this input. `verify` returns whatever the wasm module returns, and it was not executed here.

```ts
import { proofInput, prove, ready, statementBytes, verify } from "./src/zk-build"
import { build } from "./src/statements/compare"

await ready()
const { statement, witness } = build({ a: 5n, b: 3n, relation: ">" })
const { proof } = prove(proofInput(statement, witness, 8))
const { outputs } = verify(statementBytes(statement), proof)
```

The compare card reads `outputs[0].groups[0][0]`.
